# Local nudge drivers

A local wake is a nudge. The server stores `{ "mode": "local", "driver": "<id>", "target": "<target>" }` and returns those fields from `POST /api/v1/watcher/poll`. It does not know how a driver reaches the agent, and it never puts message or task content in the poll.

`driver` matches `^[a-z0-9-]{1,32}$`. The server accepts any id. `local_driver` is unconstrained text, and `delivery_mode` already allows `local`, so shipping `orca` did not need a migration. `{ "mode": "herdr", "pane": "<pane>" }` is still accepted and stored as `{ "mode": "local", "driver": "herdr", "target": "<pane>" }`.

This repository ships two drivers, `herdr` and `orca`. Each binary is a prerequisite only for its own driver. Webhook and `none` do not use either. The watcher command is the same for both (`replyslip watch` / `node replyslip.mjs watch`). The driver comes from the agent's delivery setting. The dashboard calls that mode **Local agent via herdr or Orca**. The field is **Pane** for both drivers. For Orca the agent prints the value with `echo $ORCA_PANE_KEY` inside that terminal. Install herdr 0.8.0 or newer (Apache 2.0 since 22 July 2026; earlier releases were AGPL) and put the `herdr` binary on `PATH`. For Orca, enable Settings → Experimental → CLI and put `orca` on `PATH`, or set `REPLYSLIP_ORCA_BIN` to the binary path. Orca 1.4.199 or newer is the recommended minimum: that release added `--wait-submit` and `turn_started` (the v1.4.199 tag is the first whose skill guide documents the flag, in the commit range after v1.4.198). ReplySlip does not bundle herdr or Orca, modify them, or list them as npm dependencies.

## Add a driver

1. Implement `NudgeDriver` in `packages/cli/src/drivers/`. The interface is `id`, `check()`, and `nudge(target, notice)`.
   - `check()` reports whether the tool is installed and new enough. On failure, `message` should say what to install and include a link.
   - `nudge(target, notice)` delivers the fixed notice to that target. Return `{ ok: true }` only when it landed. Return `{ ok: false, error }` otherwise. Do not send task text.
2. Register the driver in `defaultRegistry()` in `packages/cli/src/drivers/registry.ts`. `watch()` can also take a registry, which is how tests swap in a fake driver.
3. Add tests in `tests/cli.test.ts`. Cover a successful nudge (acked), a failed nudge (not acked), and an unknown driver (not acked). Call the fake driver. Do not shell out to the real tool.

At startup the watcher runs `check()` for every registered driver and logs the result. A wake whose driver is unknown, or whose check failed, is not acked. That warning is logged once per wake and driver, not on every poll. A nudge that returns `ok: false` is also not acked, so the server can offer the wake again after its 60-second lease. A nudge that returns `ok: true` is acked, and the watcher will not call `nudge` again for that wake.

herdr's `check()` runs `herdr --version` and requires `0.8.0` or newer. When herdr reports that the pane does not exist, the driver returns `no pane named <target>`. The herdr target is the agent name from `herdr agent get` (`.result.agent.name`), which the dashboard labels **Pane**. It is not the pane id. `herdr pane current --current` prints a pane id such as `w1:p1`, and the driver refuses that.

## orca

`target` is the Orca pane key, `tabId:leafId`, the value of `ORCA_PANE_KEY` in the terminal Orca started. The dashboard labels that field **Pane**, the same label as herdr. The agent prints it during setup (`echo $ORCA_PANE_KEY`). Handles are runtime-scoped and go stale when Orca restarts, so the driver never stores one. `ORCA_TERMINAL_HANDLE` is not the target.

On each wake the driver runs `orca terminal list --json` and keeps the rows whose `tabId` and `leafId` equal the two halves of the stored key. Current Orca puts both fields on each terminal in that JSON (`RuntimeTerminalSummary` in `src/shared/runtime-terminal-contracts.ts`). Plain `--json` omits `visualLayouts`. If the listed terminals do not include `leafId`, the driver repeats the list with `--include-visual-layouts`, which is the public flag that returns pane topology (`type: "terminal"` nodes carry `tabId` and `leafId`). There is no separate public CLI for the `terminal.resolvePane` RPC. A missing identity after that second list is `{ ok: false }` and the wake is requeued.

UUID leaf ids are the durable half of the pane key. `src/shared/stable-pane-id.ts` says they are used across reloads, PTY env, hook IPC, and retained rows. Renderer numeric pane ids are transient. `src/main/persistence/restoring-sessions/terminal-layout-normalization.ts` keeps a unique UUID leaf id on load and rewrites only legacy numeric ids and duplicate ids. Tab ids live on the persisted tab row (`TerminalTab.id` in `src/shared/terminal-tab-types.ts`). Orca's session restore brings tabs and splits back after quit. This repo's reading of Orca's source did not find a restart path that rewrites those tab ids. Closing the pane, or a legacy numeric key that gets normalized, mints a new leaf id. Breaking a pane out can keep the leaf UUID under a new tab id (`isEquivalentPaneKey` in `src/main/runtime/orchestration/db/pane-key-match.ts` matches the leaf alone). This driver matches both parts, so that move is a zero-match until the human saves the new key. The handle does not survive: `resolveOrchestrationPaneTerminalHandle` calls `terminal.resolvePane` with `ORCA_PANE_KEY` and uses the new handle.

The server still accepts any driver id matching `^[a-z0-9-]{1,32}$`. For herdr and every other driver, `target` stays a single line of 1–200 characters with no control characters. For `orca`, `lib/delivery.ts` requires `/^[^\s:]+:[^\s:]+$/`, no control characters, and at most 200 characters, the same rule as the dashboard in LandingBot's PR. A mismatch is `400` `validation_error`, and the issue message says the Orca pane key looks like tabId:leafId. The dashboard files in this repo are unchanged; LandingBot's PR owns that form.

- Zero matches, or more than one, returns `{ ok: false }` with a clear error. The watcher does not ack, so the wake is requeued after the lease. Nothing was typed.
- Exactly one match runs `orca terminal send --terminal <handle> --text <notice> --enter --wait-submit 10 --json`. `<notice>` is the same fixed text herdr types (`WAKE_NOTICE`), which says another agent sent something on ReplySlip. The call is `execFile` with an argument array. It is not a shell string. `orca` is taken from `PATH` unless `REPLYSLIP_ORCA_BIN` is set.
- A receipt whose stages include `turn_started` is delivered: `{ ok: true }`, and the watcher acks.
- An older host refuses `--wait-submit` before it types anything. The CLI error is `incompatible_runtime` and says the host does not support `--wait-submit`. The driver then runs the same send without `--wait-submit`. That legacy receipt uses provider `old-host` and stage `input_accepted`. Only on this fallback is `input_accepted` treated as delivered. The driver logs a warning naming Orca 1.4.199 as the recommended minimum. A current host that stops at `input_accepted` is still unproven, not delivered.
- A receipt that stops at `input_accepted` on a host that accepted `--wait-submit`, or a send that times out, is unproven. The CLI does not resend the prompt on that timeout, and a later poll must not type it again either. `{ ok: false }` is the watcher's requeue signal and would call `nudge` again, so the driver returns `{ ok: true }` and the watcher acks. The wake is acked even though Orca did not prove `turn_started`.
- An ambiguous transport failure is the exception that still gets a second `execFile`, and only when the receipt reports `--retry-request`. That second call is the same argument list plus `--retry-request <id>`. Orca replays the original request and does not inject the text again. If the retry reaches `turn_started`, the wake is acked as delivered. If it is still unproven or times out, it is acked as unproven. There is no third send.
- `terminal_handle_stale` re-lists once and sends to the replacement handle only. The first send did not land, so this is not a second prompt to the same terminal. If the new list is not exactly one different handle, the driver returns `{ ok: false }` and the wake is requeued.
- `check()` runs `orca status --json`. A failure, including a missing binary, returns `Orca isn't running or its CLI isn't enabled (Settings → Experimental → CLI)`. That failed check is not acked, so the wake stays pending until Orca is up.
